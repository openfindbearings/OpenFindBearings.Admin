# 数据管理模块 v1.1.0

版本：v1.1.0
日期：2026-10-18
上一版：v1.0.0

## 概述

数据管理模块负责 OpenFindBearings.Api 中主数据（品牌、轴承类型、轴承、商家）的浏览、搜索、新建、编辑、软删除、恢复与彻底删除，并提供轴承与商家之间的在售关系查看弹窗。替代关系已从本模块剥离，独立为「替代品管理」页（`Interchanges/Index`，侧边栏信息管理组），不再位于 `/Data/Interchanges`。

模块不持有本地数据库，全部数据经 `ApiClient`（命名 HttpClient，超时 30 秒）调用 OpenFindBearings.Api 读取与写入，页面与接口一一代理，无直连数据库路径。

## 侧边栏入口

信息管理组下「基础信息」区包含：品牌列表（`Data/Brands`）、类型列表（`Data/BearingTypes`）、轴承列表（`Data/Bearings`）、替代品管理（`Interchanges/Index`）、商家列表（`Data/Merchants`）。

## 共性设计

- 列表页：顶部为筛选表单 + 操作按钮，下方为表格，底部为分页（首页/上一页/页码/下一页/尾页）。列表页默认隐藏已删除行，勾选「显示已删除」后透传 `includeDeleted=true`，行内出现「恢复」「彻底删除」按钮。
- 品牌、类型两个列表由 API 返回全量数组，服务端渲染前在控制器内按关键字过滤与内存分页；轴承、商家、替代品由 API 服务端分页。
- 写操作成功后经 TempData 提示并重定向回列表；失败透传 HTTP 状态码或上游 `detail` / `message` 文案。
- 操作按钮按权限动态显隐（`PanelPerms.Has`），无权限者看不到按钮，控制器侧另有 action 级权限兜底。

## 1. 品牌管理（/Data/Brands）

列表接口：`GET {ApiBase}/api/admin/brands?includeDeleted={bool}`（返回 `{ success, data: [...] }` 非分页数组）。

字段（DTO `BrandItemDto`）：Id、Code、Name、Country、Level、BearingCount。列表列显示：编码、名称、产地、等级（Premium=高级 / Economy=经济 / 其他=标准）、轴承数、操作。

搜索：关键字匹配 Name 或 Code（控制器内存过滤）。

操作：

| 操作 | 控制器动作 | 上游端点 | 权限 |
|------|-----------|---------|------|
| 新建 | CreateBrand | `POST /api/admin/brands`（code,name,country,logoUrl,level） | brand.create |
| 编辑 | EditBrand | `PUT /api/admin/brands/{id}`（name,country,logoUrl,level） | brand.edit |
| 删除（软删） | DeleteBrand | `DELETE /api/admin/brands/{id}` | brand.delete |
| 恢复 | RestoreBrand | `PUT /api/admin/brands/{id}/restore` | data.restore |
| 彻底删除 | HardDeleteBrand | `DELETE /api/admin/brands/{id}/hard` | data.harddelete |

限制：编辑弹窗中「编码」置为只读（创建后不可修改，避免影响引用方）。

## 2. 轴承类型管理（/Data/BearingTypes）

列表接口：`GET {ApiBase}/api/admin/bearing-types?includeDeleted={bool}`（非分页数组）。

字段（DTO `BearingTypeItemDto`）：Id、Code、Name、Description、BearingCount。列表列：编码、名称、描述、轴承数、操作。

搜索：关键字匹配 Name 或 Code（控制器内存过滤）。

操作：

| 操作 | 控制器动作 | 上游端点 | 权限 |
|------|-----------|---------|------|
| 新建 | CreateBearingType | `POST /api/admin/bearing-types`（code,name,description） | type.create |
| 编辑 | EditBearingType | `PUT /api/admin/bearing-types/{id}`（name,description） | type.edit |
| 删除（软删） | DeleteBearingType | `DELETE /api/admin/bearing-types/{id}` | type.delete |
| 恢复 | RestoreBearingType | `PUT /api/admin/bearing-types/{id}/restore` | data.restore |
| 彻底删除 | HardDeleteBearingType | `DELETE /api/admin/bearing-types/{id}/hard` | data.harddelete |

限制：编辑弹窗中「编码」置为只读。

## 3. 轴承管理（/Data/Bearings）

列表接口：`GET {ApiBase}/api/admin/bearings?page={page}&pageSize={pageSize}&includeDeleted={bool}`，附带可选的 `keyword`、`createdFrom`、`createdTo`、`internetSource`。

字段（DTO `BearingItemDto`）：Id、PartNumber、OldNumber、BrandName、BearingType、EnglishName、Description、Image3DUrl、Image2DUrl、DataSource、CreatedAt。列表列：型号、旧型号、品牌、类型、英文名、来源、创建时间、操作。

筛选口径：

- 关键字：`keyword`（型号等），占位文案「搜索型号...」。
- 创建时间区间：`createdFrom` / `createdTo`（业务日历 `yyyy-MM-dd`）。
- 来源：`sourceFilter` 取值 `internet` / `noninternet` / 空，控制器映射为 API 的 `internetSource=true` / `false`。
- 显示已删除：`includeDeleted`。

行内视图操作：

- 替代品弹窗：点击「替代品」按钮，浏览器请求 `GET /api/proxy/interchanges/{bearingId}`（代理至公域 `GET /api/bearings/{id}/interchanges`），弹窗列：类型、品牌、型号、备注。
- 在售商家弹窗：点击「在售商家」按钮，浏览器请求 `GET /api/proxy/bearing-merchants/{bearingId}?onlyOnSale=true&pageSize=50`（代理至公域 `GET /api/bearings/{id}/merchants`），弹窗列：商家名称、状态（已认证/未认证）。点击商家行跳转 `/Data/Merchants?merchantId=...&search=...` 并自动打开该商家的在售商品弹窗。

写操作：

| 操作 | 控制器动作 | 上游端点 | 权限 |
|------|-----------|---------|------|
| 新建 | CreateBearing | `POST /api/admin/bearings`（partNumber,oldNumber,description,brandName,bearingType） | bearing.create |
| 编辑 | EditBearing | `PUT /api/admin/bearings/{id}` | bearing.edit |
| 删除（软删） | DeleteBearing | `DELETE /api/admin/bearings/{id}` | bearing.delete |
| 恢复 | RestoreBearing | `PUT /api/admin/bearings/{id}/restore` | data.restore |
| 彻底删除 | HardDeleteBearing | `DELETE /api/admin/bearings/{id}/hard` | data.harddelete |

## 4. 商家管理（/Data/Merchants）

列表接口：`GET {ApiBase}/api/admin/merchants?page={page}&pageSize={pageSize}&includeDeleted={bool}`，附带 `keyword`、`verifiedOnly`、`registeredFrom|onboardedFrom`、`registeredTo|onboardedTo`、`internetSource`、`sortBy`、`sortOrder`。

字段（DTO `MerchantItemDto`）：Id、Name、EnglishName、CompanyName、Type、ContactPerson、Phone、Email、Address、IsVerified、Status、ApplicationMode、DataSource、SubmittedAt（注册时间）、OnboardedAt（入驻时间）。列表列：名称、英文名、公司、类型、联系人、电话、认证、注册时间、入驻时间、操作。

筛选与排序口径：

- 搜索：`keyword`（名称/手机/地址等）。
- 认证页签：`verifiedOnly` 取值 空（全部）/ `true`（已认证）/ `false`（未认证）。
- 时间字段：`dateField` 取值 `registered`（注册时间，默认）/ `onboarded`（入驻时间）；起止 `dateFrom` / `dateTo`。控制器按字段映射为 API 的 `registeredFrom|registeredTo` 或 `onboardedFrom|onboardedTo`（业务日历 `yyyy-MM-dd`）。
- 来源：`sourceFilter` 映射为 API 的 `internetSource=true|false`。
- 排序：「注册时间」「入驻时间」列头可点击排序，`sortBy=registeredat|onboardedat`，`sortOrder=asc|desc`（默认最新在前）。
- 显示已删除：`includeDeleted`。

写操作：

| 操作 | 控制器动作 | 上游端点 | 权限 |
|------|-----------|---------|------|
| 新建 | CreateMerchant | `POST /api/admin/merchants`（name,companyName,englishName,contactPerson,phone,email,address,type=4） | merchant.manage |
| 编辑 | EditMerchant | `PUT /api/admin/merchants/{id}` | merchant.manage |
| 删除（软删） | DeleteMerchant | `DELETE /api/admin/merchants/{id}` | merchant.manage |
| 恢复 | RestoreMerchant | `PUT /api/admin/merchants/{id}/restore` | data.restore |
| 彻底删除 | HardDeleteMerchant | `DELETE /api/admin/merchants/{id}/hard` | data.harddelete |
| 解除归属 | DetachMerchant | `POST /api/admin/merchants/{id}/detach` | merchant.detach |

解除归属可用性（与 API 守卫同口径）：仅「生效」状态且（认领 `ApplicationMode=Claim`，或提名已有 `None` 且 `DataSource=Manual`）的商户可点；其余按钮置灰并给出说明。上游 400 文案（如「自助创建或提名新建的商户无公海数据可退回」）经 `detail` 字段透传。

在售商品弹窗：点击「在售商品」按钮，浏览器请求控制器动作 `GET /Data/GetMerchantBearings?id={merchantId}&page=...&sortBy=...&sortOrder=...`，该动作代理 `GET /api/merchants/{id}/bearings?page&pageSize&onlyOnSale&sortBy&sortOrder`。弹窗列：型号、曾用代号、类型、尺寸、品牌、价格、状态。价格列受价格配置控制：`Price.ShowNegotiableLabel` 控制「议价」角标，`Price.NumericForSorting` 控制价格列排序是否可用（关闭时点列头提示「价格排序功能已关闭」并在控制器侧拒绝 price 排序）。弹窗顶部提供当前页型号/曾用代号/品牌客户端过滤。

## 5. 商家商品状态两轴

商家商品（商家-轴承关联）的状态由两个正交维度表达，取值来自上游 API（`saleState` / `reviewStatus`）：

- 销售态 `saleState`：0=已下架、1=出售中、2=补货中。三态互斥，替代旧的在售/补货两个独立布尔。
- 审核态 `reviewStatus`：0=仓库中（商家私库，从未提交审核）、1=审核中（待平台审核）、2=已通过（平台放行）、3=已驳回（带理由，可修改重提）。

公域可见规则：`reviewStatus=已通过` 且销售态为「出售中」或「补货中」。在售商品弹窗的状态列依据上游下发的在售标志渲染「在售 / 下架」。

## 6. 替代品管理（/Interchanges/Index，独立页）

菜单名为「替代品管理」，归信息管理组，权限 `merchant.verify`。页面为服务端渲染（对齐商品审核页），列表首屏由 `InterchangesController.Index` 直取 `GET {ApiBase}/api/admin/interchanges?page&pageSize&keyword&createdFrom&createdTo&internetSource`，API 不可达时降级空表并提示，不阻断页面。

列表列：源型号/品牌、目标型号/品牌、类型、可信度、双向、来源（含来源类型小字）、更新时间、操作（编辑/删除，仅 `merchant.verify` 持有者可见）。

筛选：关键字 `keyword`（型号/品牌）、创建时间区间 `createdFrom` / `createdTo`、来源 `sourceFilter`（全部/仅互联网/仅非互联网）。

行内行 DTO（`InterchangeAdminRowDto`）字段：Id、SourceBearing、TargetBearing、InterchangeType（exact/conditional/functional）、TypeLabel、Confidence、Origin、Remarks、IsBidirectional、DataSourceType、CreatedAt、UpdatedAt。

写操作经浏览器调用 Program.cs 注册的代理端点：

| 操作 | 代理端点 | 上游端点 |
|------|---------|---------|
| 新建 | `POST /api/proxy/admin-interchanges` | `POST /api/admin/interchanges` |
| 编辑 | `PUT /api/proxy/admin-interchanges/{id}` | `PUT /api/admin/interchanges/{id}` |
| 删除 | `DELETE /api/proxy/admin-interchanges/{id}` | `DELETE /api/admin/interchanges/{id}` |
| 选取源/目标轴承 | `GET /api/proxy/bearing-search?keyword&pageSize` | `GET /api/bearings/search` |

新建弹窗字段：源轴承（搜索选取）、目标轴承（搜索选取）、替代类型（exact=标准等效替代 / conditional=条件替代（需评估）/ functional=仅供参考）、可信度（0-100）、双向替代、来源说明、备注。编辑弹窗隐藏轴承选择器，仅展示源/目标只读摘要，可改类型、可信度、来源、备注、双向。

## 7. 权限与操作限制汇总

- 品牌：brand.create / brand.edit / brand.delete / data.restore / data.harddelete。
- 类型：type.create / type.edit / type.delete / data.restore / data.harddelete。
- 轴承：bearing.create / bearing.edit / bearing.delete / data.restore / data.harddelete。
- 商家：merchant.manage（新建/编辑/删除）、merchant.detach（解除归属）、data.restore / data.harddelete。
- 替代品：merchant.verify（列表与增删改一体）。
- 「恢复」「彻底删除」仅当勾选「显示已删除」时出现在操作列；彻底删除为不可逆物理删除，需 `data.harddelete`。
- 控制器级入口权限：DataController 挂 `PanelPermission("bearing.view","brand.view","type.view","merchant.view")`（任一命中），InterchangesController 挂 `PanelPermission("merchant.verify")`。

## 8. API 对接与取数方式

命名 HttpClient 为 `ApiClient`（30 秒超时，带 BearerTokenHandler 自动附加访问令牌）。列表页与写操作由控制器服务端调用 API；行内弹窗中，替代品、在售商家走 `Program.cs` 注册的 `/api/proxy/*` 代理端点（浏览器直接 fetch），在售商品走控制器动作 `Data/GetMerchantBearings`。

## 9. 降级策略

| 场景 | 表现 |
|------|------|
| API 不可达（品牌/类型/轴承/商家列表） | 返回空列表视图并提示，页面不崩溃 |
| API 不可达（替代品列表） | 列表区显示「无法获取替代关系列表 / 连接 API 服务异常」，空态行 |
| 在售商品/在售商家/替代品弹窗请求失败 | 弹窗内显示「加载失败」 |
| 价格配置读取失败 | `PriceConfigService` 退回默认值并进入 1 分钟退避，价格列按默认口径渲染 |
