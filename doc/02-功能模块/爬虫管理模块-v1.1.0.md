# 爬虫管理模块 v1.1.0

## 概述

Crawler 项目保持纯 CronJob 运行模式（K3s 每晚 22:00 UTC 自动触发，4 小时超时，不常驻 Web 实例），因此本模块不再提供远程控制能力，仅提供**只读展示**：

- 已接入的爬虫数据源清单（从 Sync `GET /api/datasources` 动态读取）
- 统一的调度策略说明（静态文案）

## 设计原则

| 项 | 决定 | 理由 |
|----|------|------|
| 手动触发 | 不支持 | 需要 Crawler 常驻 Web 实例，违背 CronJob 不占用常驻资源的初衷 |
| 调度修改 | 不支持 | 属基础设施配置，改动频率极低，由运维通过 kubectl/Helm 修改 CronJob YAML |
| 运行历史 | 不保留 | K8s CronJob 原生留存最近 3 次 Job 历史（successfulJobsHistoryLimit: 3），kubectl get cronjob 可查 |
| 状态查看 | 不支持 | Crawler 无常驻实例，无状态 API 可读 |
| 数据源清单 | 动态读取 | 新增爬虫网站只需 Crawler 插件 + Sync 注册 IDataSource，Admin 零改动自动显示 |

各爬虫共享同一调度策略，调度信息**统一展示，不归属某个爬虫**。

## 页面设计

### 数据爬虫页（/Crawler/Index）

页面由两部分组成：

**1. 爬虫接入情况（动态表格）**

从 Sync `GET /api/datasources` 读取，过滤 `Type == Database` 的数据源（即网站爬虫），展示：

| 数据源 | 爬虫名称 |
|--------|----------|
| cbia | 中国轴承工业协会爬虫 |

**2. 调度策略（静态卡片）**

| 项 | 内容 |
|----|------|
| 调度方式 | K8s CronJob 定时任务 |
| 执行时间 | 每晚 22:00（UTC）自动触发 |
| 超时限制 | 单次运行最长 4 小时，超时自动中止，次日续跑 |
| 说明 | 爬虫统一按上述策略调度，数据写入原始库（db_raw），经 Sync ETL 流程处理后进入业务库 |

## API 调用序列

```
页面加载 → Admin HomeController.DataSources → SyncClient → Sync GET /api/datasources
```

1. 前端 `fetch('/Home/DataSources')`
2. `HomeController.DataSources` 调用 Sync `GET /api/datasources`（带 Bearer token）
3. 返回 `[{ name, displayName, supportsIncremental }]`，前端渲染表格

Sync 端点定义：

- `GET /api/datasources`（RequireAuthorization）
- 过滤条件：`DataSourceType.Database`（爬虫采集类型）
- 返回字段：`name`（源标识）、`displayName`（中文名）、`supportsIncremental`

## 降级策略

| 场景 | 表现 |
|------|------|
| Sync 服务离线 | 数据源表格显示"加载失败，Sync 服务可能离线"，调度卡片不受影响 |
| 无已接入爬虫 | 表格显示"暂未接入爬虫数据源" |
