# 用户权限模块 v1.0.1

版本：v1.0.1
日期：2026-10-18
上一版：v1.0.0

## 概述

用户权限模块覆盖 Admin 后台的登录认证、菜单与按钮级授权、用户管理、角色管理与权限目录展示。认证基于 OpenFindBearings.Identity（OpenIddict）的 OAuth 2.0 / OIDC 授权码流程；授权（面板角色与权限点）以 OpenFindBearings.Api 的 RBAC 为唯一事实源，Admin 侧不再持有本地角色/权限表，权限目录与角色均由 API 托管。

对应控制器与入口：用户管理（`UsersController`，路由 `/Users`）、角色管理（`RoleController`，路由 `/Role`）、权限管理（`PermissionController`，路由 `/Permission`，只读）、审计日志（`AuditLogController`，路由 `/AuditLog`）。

## 认证方式（OIDC 授权码流程）

Admin 作为 OpenIddict 的机密客户端，走授权码流程：

1. 用户访问 `Account/Login` 落地页，点击登录触发 `Account/LoginAction`。
2. 浏览器被重定向至 Identity `{Identity:Authority}/connect/authorize`，携带 `response_type=code`、`client_id`、`redirect_uri`（`Identity:CallbackUrl`，默认 `https://localhost:7167/callback`）、`scope`（默认 `openid profile email roles api:admin offline_access`）、`state`、`realm=openfindbearings` 与 `device_id`（浏览器首次生成后经 cookie 复用，供刷新令牌设备绑定）。
3. 用户在 Identity 登录页完成验证，回跳 `/callback`。
4. `AccountController.Callback` 用 code 经 Basic 认证（client_id:client_secret）向 `/connect/token` 换取 `access_token` + `refresh_token`，并把 `device_id` 一并提交。
5. Admin 解析 JWT 得到 sub/name/email 等，写入加密 Cookie（有效期 8 小时，滑动续期）。
6. 登出走 `Account/Logout`，清本地 Cookie 并重定向 Identity `/connect/logout`。

ID 令牌与刷新：`AdminTokenService` 负责按 exp 预刷新并回写 Cookie，`BearerTokenHandler` 在每次 `ApiClient` / `IdentityClient` 请求时附加新鲜访问令牌。

## 登录门禁与权限判定链

1. 登录回调换到令牌后，Admin 调 API `GET {ApiBase}/api/me/permissions`（Bearer），取回 `{ roles: [...], permissions: [...] }`。
2. 面板角色必须与固定集合 `{ Admin, Operator, Auditor }`（`Authorization/PanelRoles.cs`）有交集，否则拒登并提示「该账号无后台权限」。
3. 通过后把每个角色写入 `panel_role` 多值 claim、每个权限点写入 `permission` 多值 claim，并写入 `permissions_fetched_at` 时间戳。
4. 权限判定：控制器与方法挂 `[PanelPermission("key1","key2")]`（`Authorization/PanelPermission.cs`），动态策略 `Panel:key1,key2` 由 `PanelPolicyProvider` 按需生成；命中任一 `permission` claim 即通过，`panel_role=Admin` 短路全通过（避免漏配锁死超管）。
5. 视图渲染：`_Layout.cshtml` 以 `HasPerm(...)` 控制菜单分组与子项显隐；各视图以 `Helpers.PanelPerms.Has(User, "key")` 控制按钮显隐（无权限者看不到按钮）。
6. Cookie 复核：Cookie 的 `OnValidatePrincipal` 每 30 分钟重新拉取 `/api/me/permissions`，面板角色被收回即 `RejectPrincipal` 踢出，否则整体替换 `panel_role` / `permission` claim 续期；API 不可达时放行（避免抖动导致集体掉线），下轮复核重试。

## 面板角色

固定三个面板角色（`Authorization/PanelRoles.cs`）：Admin（超管，菜单与操作全通）、Operator（运营）、Auditor（审核）。

业务侧另有 API 托管的平台角色（如 Individual 等），由 API 的 RBAC 目录返回，用于用户列表角色徽章与分配。Admin 不本地保存角色定义。

## 1. 用户管理（/Users）

控制器 `UsersController`，入口权限 `user.view`。列表数据来自 Identity：

`GET {IdentityBase}/api/account/admin/users?page&pageSize&search&status&includeDeleted`

- 状态筛选 `status`：enabled（正常，默认）、disabled（已禁用=黑名单）、locked（已锁定，5 次输错密码临时锁定）、deleted（已删除，需 `includeDeleted=true`）、all（全部）。
- 页签：全部 / 后台用户 / 前端用户（前台客户端过滤：挂面板角色为后台用户，仅 Individual 为前端用户）。

列表列：用户名、姓名、邮箱、手机号、状态、角色、最后登录、操作。角色列数据来自 API 平台角色批量端点（不是 Identity 角色），并按 API 角色目录渲染中文显示名。

用户写操作：

| 操作 | 控制器动作 | 上游端点 | 权限 |
|------|-----------|---------|------|
| 新建后台用户 | Create | Identity `POST /api/account/admin/users`，随后 API `POST /api/admin/users/provision` | user.manage |
| 启用/禁用 | ToggleStatus | Identity `PATCH /api/account/admin/users/{id}/status`（body `{ enable }`） | user.ban |
| 解锁 | Unlock | Identity `POST /api/account/admin/users/{id}/unlock` | user.ban |
| 重置密码 | ResetPassword | Identity `POST /api/account/admin/users/{id}/reset-to-default` | user.ban |
| 恢复 | Restore | Identity `POST /api/account/admin/users/{id}/restore` | user.manage |
| 软删除 | Delete | Identity `DELETE /api/account/admin/users/{id}` | user.manage |
| 彻底删除 | HardDelete | Identity `DELETE /api/account/admin/users/{id}/permanent` | data.harddelete |

约束与守卫：

- 新建后台用户必须至少勾选一个平台角色（否则为进不了任何面板的孤儿账号）；App 用户走 app 端自助注册。建号成功后即调 API `provision` 预置业务行并授权，解「未登录过不能分配角色」死结；provision 失败不回滚账号，提示稍后手动补。
- 重置密码统一重置为系统初始密码（值单一事实源在 Identity 配置），成功后回显密码值供转告本人；纯前端用户（挂 Individual 且无后台角色）无密码，视图隐藏按钮且控制器再挡一层。
- 软删除采用两步链路（正常 → 禁用 → 删除，删除按钮仅出现在已禁用行），并在服务端 fail-closed 守卫：不能删除自己；目标为 Admin 且无其他启用 Admin 时拒绝（防后台锁死）；校验不可达即拒绝。删除 app 用户不回滚其商户成员/积分/收藏等业务数据。

平台角色分配（`user.assign`）：

| 操作 | 控制器动作 | 上游端点 |
|------|-----------|---------|
| 打开分配弹窗 | PlatformRoles | API `GET /api/admin/users/by-auth/{id}/roles`、`GET /api/admin/roles/all` |
| 保存平台角色 | SavePlatformRoles | API `POST /api/admin/users/provision`、`DELETE /api/admin/users/by-auth/{id}/roles/{role}` |

分配弹窗支持多选并存，目录含元数据（displayName / description / isSystemRole）；保存为差量语义（勾选态即最终态），自锁守卫：不允许移除自己的 Admin 角色；保存时无条件先 `provision`（幂等），再移除原有但本次未勾的角色。

用户列表底部还经 API `GET /api/admin/users/platform-roles` 拉取 `sub → roles[]` 字典合并渲染角色徽章与角色中文名（`GET /api/admin/roles/all`）。

## 2. 角色管理（/Role）

控制器 `RoleController`，入口权限 `role.manage`。全部读写代理 API RBAC：

| 操作 | 控制器动作 | 上游端点 |
|------|-----------|---------|
| 角色列表 | Index | `GET /api/admin/roles?page=1&pageSize=100` |
| 角色权限详情 | Permissions | `GET /api/admin/roles/{id}/permissions` + `GET /api/admin/permissions?page=1&pageSize=200` |
| 新建角色 | Create | `POST /api/admin/roles`（name, displayName, description） |
| 删除角色 | Delete | `DELETE /api/admin/roles/{id}` |
| 保存权限 | SavePermissions | `POST /api/admin/roles/{id}/permissions`（body `{ permissionNames: [...] }`） |

- 角色名解析为 API 角色 ID 走 `GET /api/admin/roles/all`。
- 新建角色：`roleName` 前端预检正则 `^[A-Za-z][A-Za-z0-9_]*`（英文标识即鉴权键），`displayName` 可为中文，`description` 为可选说明。
- 列表主显中文显示名，英文标识降为副标；`Admin` 角色在视图层不显示删除按钮（API 侧亦有系统角色守卫）。
- 权限配置页为「整表覆盖」语义：勾选清单整体提交，API 侧替换式分配。

## 3. 权限管理（/Permission，只读）

控制器 `PermissionController`，入口权限 `permission.view`。数据来自 API 权限表：`GET /api/admin/permissions?page=1&pageSize=200`。

权限点目录为只读展示（权限点等于端点过滤器中的代码常量，界面新增无意义）。展示时按权限键前缀分组，组名由前缀推导（仪表盘 / 数据管理 / 商家管理 / 数据危险操作 / 审核管理 / 任务管理 / 认证管理 / 系统配置 / 审计日志 / 其他），显示名直读 API 权限表 description。

## 4. 审计日志（/AuditLog）

控制器 `AuditLogController`，入口权限 `audit.view`。侧边栏审计日志组含两个源：

- 管理员日志：`source=identity`，取 Identity `GET {IdentityBase}/api/auditlog?page&pageSize`。
- API 日志：`source=api`，取 API `GET {ApiBase}/api/admin/audit-logs?page&pageSize`。

控制器把各源响应按统一口径解析为 `AuditLogItemDto`（兼容各项目 DTO 字段命名差异）。开源骨架仅内置 identity 与 api 两个源；其它审计源由扩展模块经 `IAdminModule.LoadAuditLogJsonAsync` 贡献（未启用扩展的部署不显示额外源）。

## 7. 降级策略

| 场景 | 表现 |
|------|------|
| `/api/me/permissions` 不可达（登录时） | 按无权限拒登并提示 |
| `/api/me/permissions` 不可达（30 分钟复核） | 放行，下轮复核重试 |
| Identity 用户列表不可达 | 空列表 + 错误提示，页面不崩溃 |
| API 平台角色/角色目录不可达 | 角色徽章降级「无角色」，目录弹窗降级空目录，不阻断主流程 |
| 审计日志源不可达 | 列表空 + 「服务可能离线」提示 |
