# 配置管理模块 v1.0.1

版本：v1.0.1
日期：2026-10-18
上一版：v1.0.0

## 概述

配置管理模块负责查看与修改系统运行时配置，并在同一页内维护积分规则、等级段位与商家集体任务。Admin 不直连数据库、不生成也不应用部署清单；配置的真相源在 OpenFindBearings.Api 侧的配置表，Admin 只通过 API 读写。

对应控制器：`ConfigController`（系统配置，入口权限 `system.view`，写操作 `system.manage`）与 `PointsController`（积分相关保存，权限 `points.manage`）。

## 配置真相源与读写链路

- 读取：`ConfigController.Index` 调 `GET {ApiBase}/api/admin/config`，返回 `{ success, data: [...] }`，按每个配置项的 `Group` 分组后以 tab 页签渲染。
- 写入：`ConfigController.Update` 调 `PUT {ApiBase}/api/admin/config/{key}`，请求体 `{ value }`，带防伪令牌，权限 `system.manage`；保存后回跳停留在原页签（`?tab=`）。
- 配置项字段：Key、Value、ValueType（bool / int / 其他）、Group、Description。
- 真相源说明：配置持久化在 API 侧数据库（SystemConfigs），Admin 不写本地库、不生成 ConfigMap、不执行 kubectl，也不依赖任何集群 RBAC。修改经 API 落库即生效，具体生效时机由各消费方（API 自身运行时）决定。

## 页签结构（/Config/Index）

配置项页签按 Group 排列，常用组在前、未知组按字母序垫底：站点设置（Site）、价格显示（Price）、系统设置（System）、业务设置（Business）。其后固定追加三个功能页签：积分任务（points）、等级段位（levels）、商家任务（merchattasks）。URL `?tab=xxx` 记忆当前页签，各保存操作回跳后停留在原页签。

### 配置项编辑

每行显示配置键、配置值、描述、编辑按钮。编辑弹窗按 `ValueType` 切换控件：

- bool：开启/关闭下拉（真值集合 `true / 1 / yes / y / on`，与非规范化值一致，避免「一打开就保存就把 true 改回 false」）。
- int：数字输入框。
- 其他：文本框。

配置键只读展示（可选中复制），提交走隐藏字段。

## 1. 积分任务（points 页签）

数据由 `ConfigController` 在渲染配置页时经 `GET {ApiBase}/api/admin/points/rules` 载入（拉取失败仅影响本页签，不阻塞配置主功能）。

列表列：动作（DisplayName）、类型标识（GrantType）、分值、每日上限、连续阶梯、状态、说明。

保存：`PointsController.SaveRules` 批量逐条代理 `PUT {ApiBase}/api/admin/points/rules/{id}`，请求体 `{ amount, dailyLimit, ladderJson, isEnabled }`，权限 `points.manage`，保存后回跳 `?tab=points`。

规则说明：每日上限为当日该动作累计发放封顶（0 不限）；连续阶梯为 JSON 数组，按连续天数取档、超出取末档（仅签到类动作生效）；勾选 false 垫底 hidden 保证停用可提交；留空阶梯表示固定分值（空串清除阶梯，null 不修改）。合规红线：积分不可充值、不可提现、不可转让。

## 2. 等级段位（levels 页签）

数据经 `GET {ApiBase}/api/admin/points/levels` 载入。

列表列：等级（Level，只读锚定）、段位名、累计获得阈值、升档礼（币）、状态。

保存：`PointsController.SaveLevels` 批量逐条代理 `PUT {ApiBase}/api/admin/points/levels/{id}`，请求体 `{ minTotalEarned, name, levelUpBonus, enabled }`；`Level` 号不在提交字段内（落档与升档礼幂等键锚定它不可改）；保存后回跳 `?tab=levels`。

规则说明：阈值=累计获得达此值落该档（只升不降）；升档礼=跨入该档一次性发币，0 不发；停用档位不可达，自动落到下一启用档。

## 3. 商家任务（merchattasks 页签）

数据经 `GET {ApiBase}/api/admin/points/merchant-tasks` 载入。

列表列：任务键（TaskKey，只读锚定）、任务名、描述、指标、目标值、周期、奖励对象、奖励分值、排序、状态。

保存与新建：

| 操作 | 控制器动作 | 上游端点 |
|------|-----------|---------|
| 批量保存 | SaveMerchantTasks | `PUT {ApiBase}/api/admin/points/merchant-tasks/{id}` |
| 新建任务 | CreateMerchantTask | `POST {ApiBase}/api/admin/points/merchant-tasks`，`taskKey` 唯一性由 API 校验 |

保存/新建后均回跳 `?tab=merchattasks`。指标口径：成员纠错采纳（corrections）、金库入账额（treasury）、新上架商品数（products）；周期为每自然周/每自然月；奖励对象为全体成员/商家金库。达标即结算由 API 每小时 Job 执行，Admin 只负责任务定义。

## 4. 价格配置

价格配置（`Price.*`）展示在「价格显示」组内，可经配置编辑弹窗修改（`PUT /api/admin/config/{key}`，`system.manage`）。

前端消费侧由 `Services/PriceConfigService`（Singleton）经 `GET {ApiBase}/api/admin/config/price` 读取并做进程内缓存：

- 缓存有效期 5 分钟；读取失败后进入 1 分钟退避，窗口内不再打接口，退回默认值。
- `ConfigController.Update` 保存 `Price.*` 键成功后调用 `PriceConfigService.Invalidate()`，使新值立即生效（不必等 TTL）。
- 消费点：在售商品弹窗的「议价」角标（`Price.ShowNegotiableLabel`）与价格列排序开关（`Price.NumericForSorting`）。

## 5. 权限

- 查看配置：`system.view`（ConfigController 入口）。
- 修改配置：`system.manage`（Update 动作）。
- 积分/等级/商家任务：`points.manage`（PointsController 入口与各保存动作）。

## 6. 降级策略

| 场景 | 表现 |
|------|------|
| `GET /api/admin/config` 不可达或非 2xx | 提示「获取配置失败」并保留空态，不再静默显示「暂无配置数据」 |
| 积分规则 / 等级段位 / 商家任务拉取失败 | 仅对应页签降级为空，不阻塞配置页其它页签 |
| 保存配置失败 | 提示「更新失败 + 状态码」，回跳原页签 |
