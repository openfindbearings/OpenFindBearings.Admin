# 部署与降级策略 v1.1.0

## 概述

Admin 作为统一管理后台，部署在 K3s 集群中。由于 Admin 依赖 3 个后端服务（API、Sync、Identity），但我们设计了优雅降级策略——任一服务离线时 Admin 仍可正常启动和导航，仅受影响的功能禁用。

Crawler 以纯 CronJob 模式运行（无常驻 Web 实例），不在 Admin 依赖范围内，Admin 仅经 Sync 数据源端点只读展示已接入的爬虫数据源。

## K3s 部署

### Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: openfindbearings-admin
  namespace: openfindbearings
spec:
  replicas: 1
  selector:
    matchLabels:
      app: openfindbearings-admin
  template:
    metadata:
      labels:
        app: openfindbearings-admin
    spec:
      containers:
      - name: admin
        image: ghcr.io/openfindbearings/openfindbearings-admin:v1.0.0
        ports:
        - containerPort: 8080
        env:
        - name: ASPNETCORE_ENVIRONMENT
          value: "Production"
        - name: ASPNETCORE_URLS
          value: "http://+:8080"
        - name: ApiUrls__OpenFindBearingsApi
          value: "http://openfindbearings-api-service:80"
        - name: ApiUrls__FindBearingsSync
          value: "http://openfindbearings-sync-api:80"
        - name: ApiUrls__OpenFindBearingsIdentity
          value: "http://openfindbearings-identity-service:80"
        - name: Identity__Authority
          value: "https://auth.abcsxl.com"
        - name: Identity__CallbackUrl
          value: "https://admin.515813.xyz/callback"
        envFrom:
        - secretRef:
            name: openfindbearings-admin-secrets
        livenessProbe:
          httpGet:
            path: /health/live
            port: 8080
          initialDelaySeconds: 10
          periodSeconds: 30
        readinessProbe:
          httpGet:
            path: /health/ready
            port: 8080
          initialDelaySeconds: 10
          periodSeconds: 30
        resources:
          requests:
            cpu: 100m
            memory: 256Mi
          limits:
            cpu: 500m
            memory: 512Mi
---
apiVersion: v1
kind: Service
metadata:
  name: openfindbearings-admin
  namespace: openfindbearings
spec:
  selector:
    app: openfindbearings-admin
  ports:
  - port: 80
    targetPort: 80
```

### 服务地址配置（ApiUrls）

代码统一读取 `ApiUrls:*` 配置节（环境变量用 `ApiUrls__*` 双下划线形式），K3s 部署直接通过 env 注入：

| 配置键 | 本地开发 | K3s |
|--------|----------|-----|
| ApiUrls:OpenFindBearingsApi | https://localhost:7183 | http://openfindbearings-api-service:80 |
| ApiUrls:FindBearingsSync | https://localhost:7206 | http://openfindbearings-sync-api:80 |
| ApiUrls:OpenFindBearingsIdentity | https://localhost:7201 | http://openfindbearings-identity-service:80 |

## 服务依赖拓扑

```
Admin 启动
  │
  ├─ 读取本地配置（无依赖）
  ├─ 检查 /health/live 探针
  │
  ├─ 仪表盘 → API + Sync（降级: 有数据就显示，无数据提示离线）
  ├─ 数据爬虫页 → Sync /api/datasources（离线: 表格显示加载失败，调度卡片不受影响）
  ├─ Sync 页面 → Sync API（离线: 禁用 ETL 操作）
  ├─ Data 页面 → API（离线: 显示"服务不可用"）
  ├─ Mapping 页面 → Sync API（离线: 不可用）
  ├─ 审核页面 → API + Sync（离线: 对应审核不可用）
  ├─ Config 页面 → API（离线: 显示"不可修改"）
  └─ 用户/权限/审计页面 → Identity API（离线: 不可用）
```

## 健康检测实现

ServiceHealthService 为后台轮询服务，并行检查 3 个服务的 `/health/live` 端点（统一路径），状态存于内存，`/Home/Status` 端点返回 JSON 供前端渲染。

```csharp
// Services/ServiceHealthService.cs
var services = new Dictionary<string, (string url, string client)>
{
    ["Api"] = (_config["ApiUrls:OpenFindBearingsApi"] ?? "https://localhost:7183", "ApiClient"),
    ["Sync"] = (_config["ApiUrls:FindBearingsSync"] ?? "https://localhost:7206", "SyncClient"),
    ["Identity"] = (_config["ApiUrls:OpenFindBearingsIdentity"] ?? "https://localhost:7201", "IdentityClient")
};

var paths = new Dictionary<string, string>
{
    ["Api"] = "/health/live",
    ["Sync"] = "/health/live",
    ["Identity"] = "/health/live"
};
```

## 降级策略矩阵

| 服务离线 | Admin 受影响功能 | 用户看到 |
|---------|----------------|---------|
| Sync | 同步管理、审核、数据源清单 | 页面显示"Sync 服务不可用"，ETL 操作禁用 |
| API | 数据管理、映射、仪表盘统计 | 页面显示"API 服务不可用"，无法查看/编辑业务数据 |
| Identity | 登录、用户/角色/权限管理、审计日志 | 已登录用户继续用（Cookie 有效期内），新用户无法登录 |
| 全部离线 | 全部功能 | 仅 Admin 首页正常，导航链接全禁用 |

## 启动顺序

```
首次部署优先：
  1. Identity（认证基础，必须先启动）
  2. API（业务数据基础）
  3. Sync（依赖 API）
  4. Admin（最后启动，不影响其他服务）
```

Admin 的设计保证了启动不依赖任何服务——没有强制等待、没有启动失败连锁。
