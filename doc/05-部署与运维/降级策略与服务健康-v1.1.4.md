# 部署与降级策略 v1.1.4

版本：v1.1.4
日期：2026-10-18
上一版：v1.1.3

## 概述

Admin 作为统一管理后台，部署在 K3s 集群中。由于 Admin 依赖 2 个后端服务（Api、Identity），我们设计了优雅降级策略——任一服务离线时 Admin 仍可正常启动和导航，仅受影响的功能禁用。

## deploy 目录结构

仓库根 `deploy/` 仅存放脱敏部署模板，供自部署参考；真实域名与密钥不入库。

```
deploy/
+-- deployment.yaml                — Deployment + Service（命名空间 openfindbearings）
+-- ingress.yaml                   — Ingress（cert-manager + nginx）
+-- secrets/
|   +-- admin-secret-template.yml  — Secret 模板（占位符替换真实值后 apply）
+-- README.md                      — 部署步骤与占位符说明
```

## K3s 部署清单

### Deployment（deploy/deployment.yaml）

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: openfindbearings-admin
  namespace: openfindbearings
spec:
  replicas: 1
  revisionHistoryLimit: 5
  selector:
    matchLabels:
      app: openfindbearings-admin
  template:
    metadata:
      labels:
        app: openfindbearings-admin
    spec:
      imagePullSecrets:
      - name: ghcr-pull-secret
      containers:
      - name: openfindbearings-admin
        image: ghcr.io/openfindbearings/openfindbearings-admin:latest
        ports:
        - containerPort: 8080
        env:
        - name: ASPNETCORE_ENVIRONMENT
          value: Production
        - name: ASPNETCORE_URLS
          value: "http://+:8080"
        - name: ApiUrls__OpenFindBearingsApi
          value: "http://openfindbearings-api:80"
        - name: ApiUrls__OpenFindBearingsIdentity
          value: "http://openfindbearings-identity:80"
        - name: Identity__Authority
          value: "https://<your-identity-domain>"
        - name: Identity__CallbackUrl
          value: "https://<your-admin-domain>/callback"
        - name: Identity__ClientSecret
          valueFrom:
            secretKeyRef:
              name: openfindbearings-admin-secrets
              key: Identity__ClientSecret
        livenessProbe:
          httpGet:
            path: /health/live
            port: 8080
          initialDelaySeconds: 10
          periodSeconds: 30
        readinessProbe:
          httpGet:
            path: /health/ready
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 10
        resources:
          requests:
            memory: "128Mi"
            cpu: "100m"
          limits:
            memory: "256Mi"
            cpu: "500m"
---
apiVersion: v1
kind: Service
metadata:
  name: openfindbearings-admin
  namespace: openfindbearings
spec:
  selector:
    app: openfindbearings-admin
  ports:
    - port: 80
      targetPort: 8080
  type: ClusterIP
```

> 备注：模板中曾额外注入 `ConnectionStrings__DefaultConnection` 环境变量，而 Admin 已不直连数据库、不再读取任何连接串（`appsettings.json` 无连接串、代码无 DbContext）。该环境变量与 `secrets/admin-secret-template.yml` 中的 `connection-string` 键属历史残留，待后续与代码一并清理（本文件如实记录现状）。

### Ingress（deploy/ingress.yaml）

- `ingressClassName: nginx`，`tls` 由 cert-manager（`letsencrypt-prod`）自动签发。
- `nginx.ingress.kubernetes.io/proxy-buffer-size: "32k"`：登录回调写入的多段 chunked auth cookie 响应头较大，默认缓冲不足会触发 "upstream sent too big header" 502，故调大缓冲。
- 主机名占位符 `<your-admin-domain>`，部署时替换为真实域名。

### Secret（deploy/secrets/admin-secret-template.yml）

| 键 | 说明 |
|----|------|
| `Identity__ClientSecret` | OAuth 客户端密钥（替换占位符后 apply） |

## 服务地址配置（ApiUrls）

代码统一经 `Helpers/ApiUrlResolver.cs` 读取 `ApiUrls:*` 配置节（环境变量用 `ApiUrls__*` 双下划线形式），K3s 部署直接通过 env 注入：

| 配置键 | 本地开发 | K3s |
|--------|----------|-----|
| ApiUrls:OpenFindBearingsApi | https://localhost:7183 | http://openfindbearings-api:80 |
| ApiUrls:OpenFindBearingsIdentity | https://localhost:7201 | http://openfindbearings-identity:80 |

未配置时的本地回退默认值集中在 `ApiUrlResolver`（Api 7183、Identity 7201）。

## 配置优先级

配置来源按以下优先级生效（后者覆盖前者）：

```
1. appsettings.json                （镜像内默认）
2. appsettings.{Environment}.json  （如 appsettings.Development.json）
3. appsettings.pro.json            （可选扩展模块覆盖配置，开源无此文件即无副作用）
4. 环境变量                         （部署时注入，优先级最高）
```

实现要点（`Program.cs`）：先按 ASP.NET Core 默认顺序加载 `appsettings.json` 与环境相关 JSON，随后追加可选 `appsettings.pro.json`，最后再 `AddEnvironmentVariables()`。因此扩展模块覆盖配置仍低于部署环境变量，部署时注入的值（如各服务基地址）始终生效。

## 服务依赖拓扑

```
Admin 启动
  |
  +- 读取本地配置（无依赖）
  +- 健康检查探针（进程内健康检查，无外部依赖）
  |
  +- 仪表盘 -> API（降级: 有数据就显示，无数据提示离线）
  +- Data 页面 -> API（离线: 显示"服务不可用"）
  +- 审核页面 -> API（离线: 对应审核不可用）
  +- Config 页面 -> API（离线: 显示"不可修改"）
  +- 用户/角色/权限/审计页面 -> Identity API 与 API（离线: 不可用）
```

## 健康检测实现

Admin 有两类健康概念：

- 进程内探针（`Program.cs` 的 `MapHealthChecks`）：`/health`、`/healthz`、`/health/live`（`Predicate` 恒假，仅探活）、`/health/ready`（全部检查）。K8s 的 liveness 探针指向 `/health/live`，readiness 探针指向 `/health/ready`。
- 后端服务健康面板（`Services/ServiceHealthService.cs`）：并行探测两个后端服务各自的 `/health/live`，状态存于内存，`/Home/Status` 端点返回 JSON 供前端渲染。

```csharp
// Services/ServiceHealthService.cs（内置检查项：Api、Identity；扩展模块可经 IAdminModule 追加）
var services = new Dictionary<string, ServiceEndpoint>
{
    ["Api"] = new(ApiUrlResolver.Api(_config), "ApiClient", "/health/live"),
    ["Identity"] = new(ApiUrlResolver.Identity(_config), "IdentityClient", "/health/live")
};
```

## 降级策略矩阵

| 服务离线 | Admin 受影响功能 | 用户看到 |
|---------|----------------|---------|
| API | 数据管理、仪表盘统计、审核处置 | 页面显示"API 服务不可用"，无法查看/编辑业务数据 |
| Identity | 登录、用户账号管理及其令牌刷新 | 已登录用户继续用（Cookie 有效期内），新用户无法登录 |
| 全部离线 | 全部功能 | 仅 Admin 首页正常，导航链接全禁用 |

## 启动顺序

```
首次部署优先：
  1. Identity（认证基础，必须先启动）
  2. API（业务数据与权限目录基础）
  3. Admin（最后启动，不影响其他服务）
```

Admin 的设计保证了启动不依赖任何服务——没有强制等待、没有启动失败连锁。
