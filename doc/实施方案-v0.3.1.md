# Admin 项目实施方案 v0.3.1

> 版本：v0.3.1 | 日期：2026-10-18 | 上一版：v0.3.0
> 状态：P0-P6 全部完成；本文档按代码现状校正

## 一、现状概览

Admin 是 Razor MVC 后台，**没有本地数据库、没有本地数据表、没有 EF 迁移**：

- 早期设计的 `db_admin` 四表（`admin_audit_logs`/`admin_user_roles`/`admin_role_permissions`/`admin_configs`）**已整体废弃删除**，Admin 不再持有数据库连接串。
- 原本地权限枚举（`PermissionKey`，17 个 `Bearing*` 键）**已废弃**；权限目录与角色统一由 API 托管（单一来源，`GET /api/admin/permissions`、`/api/admin/roles*`），Admin 只做展示与转发。
- 面板角色由 `Authorization/PanelRoles.cs` 固定为三个：`Admin`、`Operator`、`Auditor`；权限判定走 `PanelPermission` 策略（`panel_role == Admin` 短路放行）。
- 后端集成（API / Identity 端点清单、代理端点、健康检测、扩展点）见《各服务API集成设计 v1.7.0》；页面与端点的逐条映射见《Admin功能需求与后端服务映射 v1.42.0》（权威）。

## 四、权限与角色

- **单一来源**：权限目录（键 + 显示名 + 分组）与角色定义均存于 API；Admin 的 `PermissionController`、`RoleController` 直接转发，本地不再维护常量表。
- **判定链**：登录回调后加载 `GET /api/me/permissions` → 写入 cookie/Claims → `PanelPermission` 策略按需校验 → 视图用 `HasPerm(...)` 决定菜单与按钮可见性。
- **面板角色**：`Admin`（全放行）、`Operator`（业务操作）、`Auditor`（只读审计）。
- **Admin 侧审计**：本地不再落审计表，管理员操作日志经 Identity 审计、业务操作日志经 API 审计。

## 五、扩展点

Admin 为"未启用本仓库全部能力的部署方"预留了模块化扩展，机制与槽位清单详见《各服务API集成设计 v1.7.0》第七节（`IAdminModule` 的路由/服务/健康探测注入、侧边栏注入、仪表盘 JSON 增强、审计来源扩展、`Views/Ext/{key}.cshtml` 槽位）。本仓库开源版本不含任何模块实现，故所有槽位空置不渲染。
